# Code review — 2026-10-19

Scope: the whole repository at `9445a1d21` (main). That covers:
- every tracked source file and the tests;
- the stdlib's Graphix sources, the examples and the book;
- the IDE tooling and the `graphix-lang` skill.

The review also re-ran the 530 repros that the 2026-10-12 review's CRs cite. It
paid special attention to the work landed since then that has not soaked yet:
- walk pruning;
- kind markers for composite forms;
- the `NoError` bound;
- "a wake is a resume, never a rebirth";
- compile-task contexts.

`../netidx` was out of scope except where Graphix reaches it.

## How to read this

- Every finding has an id, such as `c-pattern-01` or `x-kind-markers-03`. Its CR
  in the code ends with that id:
  `// CR claude for <eric|claude>: [tag/severity] text (id)`.
  - Eric's queue: `cr list --for eric`.
  - One severity: `cr list --tag bug --min-sev high`.
  - One finding: `cr show c-pattern-01`.
- Tags:
  - `bug`: wrong behaviour reachable today.
  - `risk`: a hazard not yet shown to be reachable.
  - `test-gap`, `doc-drift`, `structure`, `perf`, `readability`, `style`,
    `dead`.

  The severity is the reviewer's.
- **No finding was independently verified.** This round had no verifier phase,
  by Eric's decision: in past rounds the verifiers confirmed about 95% of
  findings. Instead, each reviewer was told to confirm by running wherever a
  program could reach the code, and to drop what it could not substantiate.
  Each CR says how its finding was established:
  - `probe: design/review-2026-10-19/repro/<file>` means the reviewer ran it
    and saved the repro.
  - "Found by reading; not run." means it came from the code alone.

  453 of the 748 findings were shown by running a program. Every one of the 59
  critical and high findings was. I re-ran the two critical repros myself, and
  both reproduce.
- Repros are in `design/review-2026-10-19/repro/`. Each file's header gives:
  - the command;
  - the expected output;
  - what HEAD prints.

  Most run as `graphix --no-cache <file>` or `graphix-fuzz check <file>`. A
  `.rs` repro is an integration test: copy it into the named crate's `tests/`
  to run it. The directory also holds probes that no CR cites.
- Duplicates were merged mechanically when they had the same file, a nearby
  line and a similar title. The kept CR says "Also reported as (…)". One root
  cause reported at different sites keeps a CR at each site; the themes below
  name the clusters.
- Drift in `CLAUDE.md` is not written as CRs. It is listed at the end of this
  document.

## How the review was done

The tree was cut into 91 units of about 2–4k lines each. One reviewer read
each unit line by line. 28 more reviewers each took one concern across the
whole repository:
- **Adversarial semantic probes:**
  - firing and wake;
  - collections and kernels;
  - seq, errors and references;
  - generics;
  - patterns;
  - walk pruning;
  - kind markers.
- **Robustness and contracts:**
  - stack depth;
  - images;
  - unsafe code;
  - panics;
  - security;
  - concurrency;
  - the node trait contract;
  - builtin effect classes;
  - parallel evaluation.
- **Performance, measured:**
  - compile-time scaling;
  - run-time scaling.
- **Tools and hygiene:**
  - the formatter;
  - the language server, driven over stdio;
  - duplication;
  - doc drift.
- **Re-runs:** six reviewers re-ran the 530 cited repros of the 2026-10-12
  review. Each classified its repros as fixed, still reproducing, regressed or
  obsolete, and tried a variant of each narrow fix.

There was no verify, vet or audit phase. The run used 119 agents and about
34M subagent tokens, which is a small fraction of the 10-12 round.

## Overall

The core machinery is in good health, and the reviewers said so in nearly
every cross-cutting area:
- **Firing and wake:** 64 adversarial probes, all of which agree across
  node-walk and JIT, cold and warm images, forked and serial, and pruned and
  unpruned runs.
- **Walk pruning:** 34 probes plus a reactive fuzz run under
  `GRAPHIX_PRUNE=audit`, with no divergence. The marking discipline holds; one
  gap, x-prune-01, is below.
- **Unsafe code:** every safety contract traced is upheld.
- **Typechecker speed:** linear on every realistic family. The largest
  examples check in 0.06–0.12 s even on debug binaries.
- **Formatter:** idempotent over all 2286 `.gx`/`.gxi` files in both repos.
- **LSP:** the server is in good shape.
- **The 10-12 fixes:** almost all of them hold, including variants at other
  sites.

The defects cluster at the edges of the new work and in the stdlib:
- the data boundaries of the kind markers;
- builtins that predate the no-rebirth ruling;
- rank-2 and pattern typing over unions and abstract types;
- conversions of numbers through `f64`.

## Themes

1. **Pattern typing over unions, structs and abstract types (critical).**
   - c-pattern-01: an exhaustive struct pattern `{x, y}` matches a wider
     struct, which types the wrong field and panics the JIT.
   - The pattern narrowing and literal pool mishandle unions of one shape:
     c-pattern-02/03/04 and x-typecheck-patterns-01/02/03/05/07.
   - x-rerun-6-02: an irrefutable let over a same-shape union is still
     refused.
2. **Fusion keyed by expression id (critical).** In f-mod-lowering-01, two
   callback instances in one region share an ExprId. One of them calls the
   other's kernel, which gives a wrong answer or a Cranelift verifier panic.
   Nearby:
   - f-call-flow-01: a value-shaped argument into a composite slot aborts the
     process.
   - tests-fusion-traits-01: kernels run user `Eq`/`Ord`/`Display` impls on
     bottom placeholders, so a JIT-only effect runs.
   - rt-01: an embedder's wrong-typed set kills the runtime only under fusion.
   - f-mod-lowering-02/03: fused calls evaluate their arguments in formal
     order, so raises come out reordered.
3. **Kind markers at the data boundary (new work).** The core holds. But
   writers and readers choose union members and keys from stripped data:
   - x-kind-markers-01..05 and t-rep-01..03 cover the writers and readers
     themselves.
   - Map and db keys that differ only in kind collide:
     http-sqlite-db1-01 and x-kind-markers-02/03.
   - Markers leak into text through `sprintf`, `ParseError` and error
     messages: x-panics-05, x-builtin-effects-01, collections-str-01/02,
     x-engine-collections-01 and x-rerun-5-03.
4. **The no-rebirth ruling is not applied in the stdlib.** Several builtins
   still reset or drop state at a sleep, where a wake must resume:
   - queuefn: core-aux-01/02, x-node-contract-02, x-builtin-effects-03.
   - throttle: x-engine-firing-01, x-builtin-effects-04, core-lib-02.
   - iter and range: x-engine-firing-02, core-lib-01.
   - lines_batched: x-node-contract-01, sys-io-01.
   - array::group: collections-str-05.
   - x-engine-firing-03: an event source cleared at its sleep bottoms the
     state built on it, so `count(timer)` blanks at re-entry. This one needs a
     ruling.

   In the compiler, the wake re-raise compares against `slept_at` and loses
   writes in the deselect cycle: c-bind-01/02 and tests-select-01. A nested
   seq answers its previous run's value: tests-seq-01.
5. **Rank-2 and quantifier rules.** The check and the build disagree, or the
   check is unsound:
   - t-fntyp-01/02/03;
   - tests-types-01/02;
   - x-typecheck-generics-01/02/03/05;
   - t-tvar-01 and t-contains-01/02;
   - tests-fusion-traits-03.

   Several of these need Eric's ruling.
6. **Numbers through f64.** Decimal and large-integer reads lose digits or are
   refused, and sorts misorder integers above 2^53:
   - x-panics-01, t-cast-setops-05, small-pkgs-02;
   - x-engine-collections-03/04/05;
   - collections-str-03;
   - tests-types-03/04, where the numeric-union order is for Eric.
7. **Parallel evaluation and parallel compile.**
   - x-parallel-01: a block's runs never fork, because their ForkSites are
     never decided.
   - x-parallel-02: `DEFAULTS_IN_CHECK` leaks into stolen compile jobs.
   - Parallel module checks race or panic on `Cast` impls:
     c-module-traits-01 and t-env-01.
   - c-analysis-branch-01/02/04 are plan-independence gaps.
8. **Dynamic modules and caches.**
   - A reload keeps the old lambdas and core-trait impls: c-module-traits-02
     and tests-fusion-traits-02.
   - Program entries go stale:
     - a netidx resolver miss records no probe: sys-net-01, shell-02;
     - a probed path through a file or a dangling symlink: x-image-02;
     - the entry is keyed by the path as given but verified by its
       canonical path: shell-05.
   - shell-01: `--warm` runs the program's first cycle, effects included.
9. **`sys::net::publish #on_write` receives uncast data.** A remote write
   panics a function-typed handler, or is dropped:
   - gx-stdlib-01, tests-lib-b2-01/02;
   - x-panics-02, x-builtin-effects-02, sys-net-03.
10. **Stack depth in the JIT and the stdlib.** Cross-kernel calls skip the
    stack check (c-callsite-01). `Generation::load` recurses per callee level
    (x-rerun-6-01, f-jit-01). The tui widget compiler overflows at about 135
    levels (x-stack-01), and handlebars aborts on nested blocks (x-panics-03).
11. **The fuzzer's reject pins are still partly vacuous.** In fuzz-lib-b-01,
    16 of 79 reject pins pass on a parse error or on an unrelated rule. The
    oracle has two blind spots, fuzz-lib-a-02/03, and three typemorph families
    report false LEAK or MISPLACED verdicts, fuzz-mutate-01/02/03.
12. **Performance.**
    - x-perf-runtime-01: `array::iter` and `map::iter` are quadratic, because
      the write FIFO pops with `SmallVec::remove(0)`.
    - Identity hashing on ids that share their top bits gives up to a 4.5x
      sawtooth.
    - c-cost-misc-01: a settled kernel loop still probes 16 slots per run.
    - tests-lib-b1-01: a deep node-walked recursion is roughly cubic under
      Auto.
    - x-rerun-2-01: a fusion refusal prints the region type, which takes
      2^n time and runs out of memory on shared types.
13. **The GUI and TUI** have many medium edge bugs:
    - window and icon sizes that panic winit;
    - chart ranges and tooltips;
    - slider lattices;
    - touch input;
    - `tui::exit` and the display's normal stop exiting with status 130
      (tui-core-01, gui-core-02);
    - examples whose scrolling is hard-coded (examples-tui-01/02/03,
      book-ui-a-03).
