# Code review — 2026-10-12

Scope: the whole repository at `7324207f` (main): every tracked source file,
the tests, the stdlib's Graphix sources, the examples, the book, the IDE
tooling and the `graphix-lang` skill. It also covers the CR-fix campaign since
the last review (`b26d14ad..7324207f`), and it re-runs every repro from
`design/REVIEW-2026-10-05.md`. `../netidx` was out of scope except where
Graphix reaches it.

## How to read this

- Every finding has an id (`c-pattern-01`, `t-cast-setops-03`, …). Its CR in
  the code ends with that id:
  `// CR claude for <eric|claude>: [tag/severity] text (id)`.
  - Eric's queue: `grep -rn 'CR claude for eric'`.
  - One severity: `grep -rn '\[bug/critical\]'`.
  - One finding and the CRs that cite it: `grep -rn '(c-pattern-01)'`.
- Tags:
  - `bug`: wrong behaviour reachable today.
  - `risk`: a hazard not yet shown reachable.
  - `test-gap`, `doc-drift`, `structure`, `perf`, `readability`, `style`,
    `dead`.

  The severity is the verifier's, or the vetter's, or the reviewer's for an
  unverified finding.
- A CR's text says how far it was checked:
  - A verified correctness finding names its repro (`probe: design/...`).
  - A CR ending in "Unverified: the reviewer's report, not checked by a
    verifier." was never checked. Treat it as a lead and run it before acting
    on it.
- Repros are in `design/review-2026-10-12/repro/<id>.gx`; a few are `.sh`,
  `.py`, `.rs` or a directory. Each one's header gives:
  - the command;
  - the expected output;
  - what HEAD prints.

  Most run as `graphix --no-cache <file>` or `graphix-fuzz check <file>`. A
  `.rs` repro is an integration test: copy it into the named crate's `tests/`
  to run it. The directory also holds the reviewers' own probes, so not every
  file there is cited by a CR.
- One defect may carry several CRs. Reports of the same thing at the same place
  were merged: the kept CR says "Also reported as (…)". Reports of one root
  cause at different sites were kept apart, so each site keeps its CR. The
  clusters are named in the themes below.
- Drift in `CLAUDE.md` and defects in `../netidx` are not written as CRs. They
  are listed at the end of this document.

## How the review was done

The tree was cut into 90 units of about 2–3k lines each. The units include the
book and the skill, which no earlier review covered. One reviewer read each
unit line by line. 38 more reviewers each took one concern across the whole
repository:
- adversarial semantic probes: firing and wake, collections and kernels,
  seq/errors/references, generics, patterns;
- stack depth, images, unsafe code, panics, security and concurrency;
- the node trait contract, builtin effect classes and parallel evaluation;
- compile-time and run-time performance scaling, measured;
- the formatter, and the language server driven over stdio;
- duplication, allocation, invalid states, error quality and doc drift;
- six reviews of the CR-fix campaign's diffs (`x-fix-*`);
- eight re-runs of the 631 old repros (`x-rerun-*`). Each old repro was
  classified as fixed, still reproducing, regressed differently or obsolete,
  and a variant of each fix was probed.

Each correctness finding (bug or risk, medium or above) then went to its own
verifier. The verifier tried to refute it and to reproduce it by running a
program against the debug binaries built at HEAD. Minor findings were vetted
per unit for accuracy and value. A third agent re-ran the repro of each
confirmed critical or high finding.

The run stopped before it finished, and Eric decided to land what was there.
So:
- 51 findings no verifier or vetter reached went in as CRs marked
  "Unverified". They are listed in their own table below.
- The independent re-run audit covered only 26 of the 103 confirmed
  critical/high findings. All 26 reproduced.
- Duplicates were merged mechanically (same file, nearby line, similar title)
  rather than by a reader.

Nothing in the tree was changed except:
- the CR comments;
- this document;
- `design/review-2026-10-12/`.

With the CRs in place the workspace is still rustfmt-clean, every changed
`.gx`/`.gxi` file still parses, and `cargo test` passes (see Numbers). Some CRs
in `.gx`/`.gxi` files were placed by line number, which can land a comment
where the grammar refuses one (between a doc and its item, inside a parameter
list). Those were moved up to the nearest legal line, which can be one item
above the code they discuss.

## What matters most

The fix campaign since the last review held up well. Of the 631 old repros,
the large majority now give the ruled answer, and most fixes survive a variant
at a sibling site. The defects that remain mostly follow one pattern: **a rule
fixed at one site of several**. The fix applies where the original repro
pointed, and the same rule is still broken at the next site. The themes below
group the critical and high findings. The tables list everything.

### 1. The fuzzer's must-reject pins test nothing

eb97e70d made a comment legal only on its own line. `Subject::parse` still
wraps a program as `let result = <body>` on one line, so a body that starts
with a `//` line is now a parse error. As a result:
- every `// expect: reject` corpus pin (81–83 of them) passes on that parse
  error, whatever the program says;
- `graphix-fuzz check|run|minimize` on any file with a header comment, every
  old repro included, reports a vacuous `AGREE (reject)`.

Seven reviewers found this independently:
- `fuzz-lib-b-01`, `fuzz-main-aux-02`, `tests-select-01`;
- `x-fix-fuzz-tests-01`;
- `x-rerun-1-01`, `x-rerun-3-01`, `x-rerun-6-02`.

Fix this first. Until it is fixed the regression gate cannot see any refusal
that stops being a refusal. Read any "AGREE (reject)" in this review's repros
with that in mind: the verifiers stripped the headers before trusting one.

### 2. Type soundness through patterns, type tests and casts

A well-checked program can still bind or store a value of the wrong type. The
JIT then trusts the type and panics.

**Patterns over unions** type their binds from one member while the run-time
test admits them all:
- `x-typecheck-patterns-01` (critical): a union type test with a constructor
  pattern.
- `c-pattern-03`: a tuple union.
- `c-pattern-04`: a union of collections.
- `x-typecheck-patterns-02`: same-shaped members.

**Or-patterns:**
- `c-pattern-01` (critical): an or-alternative's struct test ignores field
  names, so an `i64` bind holds a string.
- `c-pattern-02` (critical): `fresh_ids` frees or-names and captures inside an
  Abstract payload.

**Coverage:** `c-pattern-05` (`Reach::new` decides `wildcard` before narrowing)
and `t-cast-setops-07` both leave coverage holes.

**Abstract types:** the run-time test compares parameters covariantly where
the check is invariant, so `Cell<i64>` matches `Cell<[i64, null]>` and null is
written to an `i64`:
- `t-cast-setops-01` (critical);
- `x-fix-types-02`.

`tests-types-02`: a cast to a nominal abstract type checks only the id and the
parameters.

**References are bare u64s at run time.** A select over `Any` reads one and
can forge one:
- `x-invalid-states-01`, `x-fix-types-03`;
- `t-cast-setops-02`: `rep_collision` ignores mutability, so `&T` becomes
  `&mut T`.

**Casts:**
- `t-cast-setops-03`, `x-security-02`, `x-engine-collections-01`: a union cast
  takes the first member that converts, and a cast to a primitive takes an
  array's first element. So `cast<i64>([7, 8, 9])` is 7, and an out-of-range
  number becomes null, `true` or a string.
- `t-cast-setops-04`: a struct cast fills a missing string field with
  `"null"`.
- `t-cast-setops-05`, `t-cast-setops-06`, `x-rerun-5-01`: list and array
  readings by shape drop elements in json, toml and `str::parse`.

**A raised struct shaped like an `ErrChain`** is typed as itself but delivered
rewritten:
- `x-engine-seq-errors-01`, `t-typ-mod-02`, `tests-lang-rest-a-01`.

**The value restriction** instantiates only a top-level function type. A
lambda inside a written struct or tuple stays generic:
- `tests-types-01`.

### 3. The check and the build still disagree

The CLAUDE.md rule is that elaboration refusing what the check accepted is a
type-system bug. These are instances of it, or of the check accepting too
much.

**The hidden-default check** covers only a call argument whose formal is
exactly `fn(..)`. A `let`, a field, an element, a connect or a rank-2 slot
slips through:
- `c-callsite-02`, `tests-functions-01`, `x-typecheck-generics-04`.

**Bounds:**
- `x-fix-types-01`: an inexact bound conjunct never reaches an open cell, so
  `t-contains-08` is only half fixed.
- `t-fntyp-01`: the constraint view drops a bound nested in another bound.
- `x-typecheck-generics-03`: a bound containing `Any` implies
  `Ordered`/`Discernible`/`Concrete`.
- `tests-modules-image-01`: an interface `val` over a compound of a signature
  variable hides `Discernible`/`Ordered`/`Singleton`.
- `x-typecheck-patterns-05`: an open union member passes the runtime-form check
  at the definition and fails per instance.

**Other:**
- `x-typecheck-generics-01`: a run-time bind against a rank-2 formal commits
  the shared quantifier copy.
- `c-module-traits-01`: a trait method's type variable named like the impl
  head's refuses a valid impl.
- `x-rerun-6-01`: `could_match` refuses every select over `'c<..>`.

### 4. The checker can hang or exhaust memory

### 5. Sleep, wake and firing

A resumed instance that is not treated as a wake loses its `<-` state and the
fires it missed. This happens to collection slots after a bottom source and to
a dynamic callee back from bottom. One defect, several sites:
- `c-node-mod-01`, `c-bind-01`, `x-engine-firing-02`;
- `tests-lang-rest-b-01`, `c-callsite-01`, `x-rerun-7-02`.

Related:
- `x-engine-firing-01`: an outer wake's WAKE-only republish spends an inner
  select's real catch-up bit.
- `core-lib-01`: raw core builtins emit `TagValue::fired` and drop WAKE.
- `core-aux-01`: the opt HOFs tag a new answer with the callback's tag alone.

**Effects repeated at a wake:**
- `http-sqlite-db1-02` and `db2-02`: an async builtin that acts on the world
  runs again at its arm's wake, so a sqlite INSERT is duplicated.
- `x-fix-nodes-01`: the arm-sleep classification sees a raise or a write only
  when it is written in the arm itself. Moving code into a helper changes what
  re-entry does.
- `sys-io-04`: `fs::watch` never rebuilds after a wake.

**Elsewhere:**
- `c-select-seq-01`: a guard below the taken arm runs over the value an
  earlier arm claimed, and its effects fire.
- `x-invalid-states-03`: after an abort, `Catch` counts a stale delivery as a
  raise.
- `c-module-traits-02`: an inside write to an exported `val` is lost when an
  outside write lands in the same cycle.

**seq:**
- `t-seq-01`: `a <- pc ~ v` loses an async answer on every run after the
  first.
- `t-seq-02`: a step whose call sits only in an untaken arm never completes.
- `x-engine-seq-errors-02`: a call-free `x?` step reads `x` only at entry.

node-walk/JIT divergence in what gets printed:
- `f-mod-lowering-01`, `x-fix-fusion-01`.

**Selects:**
- `f-select-01`: the guard prologue skips the arm's predicate.
- `f-select-02`: `` `Count(null) `` matches `` `Count(0) ``.

**Calls and loops:**
- `f-call-flow-01`: a callee first called from inside another fused callee

- `f-call-flow-02`: the native tail loop runs new depths without the init

## Performance, structure and docs, in short

**Run time.** `x-alloc`, `x-perf-runtime`: the node-walk visits every live
collection slot and every recursion activation on every cycle, even when
nothing they read changed. An idle 8000-element map with an unfused callback
adds about 2 ms to every unrelated cycle (debug build). Smaller items:
- a `#numeric` sort re-casts both operands per comparison;
- an explicit `T as x` arm walks the value with `is_a` on every update.

**Compile time.** `x-perf-compile`: `--check` is linear in every family
measured, 60–90 ms on the largest examples. The build after it is superlinear
in deep static call chains:
- dependency summaries are recomputed per block and per fork site;
- first-cycle fork decisions under `auto`;
- fusion's callee discovery.

An 800-deep chain takes 32 s to build against 0.4 s to check.

**Language server.** `x-lsp-probe`: edits are never coalesced over stdio,
because the stdio channel is bounded(0). Every `didChange` runs a full check,
and opening 36 netidx-admin files took 17.5 s to the first answer.

**Structure and invalid states.** `x-dup`, `x-invalid-states`:
- At the line level the code is DRY. The duplication that matters is one rule
  implemented in several places that have drifted apart:
  - two "naked" value printers;
  - three rendering sites;
  - six hand-rolled callback builtins that treat a bottom input differently.
- At the Rust level the core types hold their invariants. The one serious
  invalid state is the language's run-time form of a reference (theme 2).

**Unsafe code.** `x-unsafe`: no reachable UB found.

**Stack.** `x-stack`: every AST shape passes at its deepest admitted depth.
The one unguarded walk left is the derived `Debug` of `Type`/`TVar`.

**Docs and the skill.** `x-doc-drift`, `lang-skill`, `book-*`:
- About seven CLAUDE.md fixes from the last review were never applied (listed
  at the end).
- The skill's stdlib summary is wrong in several places.
- The book has stale package lists and examples, and nothing checks its inline
  code blocks.
