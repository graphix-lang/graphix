## How to read this

- Every finding has an id, such as `c-lambda-01` or `x-sleep-wake-03`. Its CR
  in the code ends with that id:
  `// CR claude for <eric|claude>: [tag/severity] text (id)`.
  - Eric's queue: `cr list --for eric` (153).
  - One severity: `cr list --tag bug --min-sev high`.
  - One finding: `cr show c-lambda-01`.
- Tags: `bug` (wrong behaviour reachable today), `risk` (a hazard not yet
  shown to be reachable), `test-gap`, `doc-drift`, `structure`, `perf`,
  `readability`, `style`, `dead`. The severity is the reviewer's.
- **No finding was independently verified.** As in the last two rounds there
  was no verifier phase. Each reviewer was told to confirm by running
  wherever a program could reach the code, and to drop what it could not
  substantiate. Each CR says how its finding was established:
  - `probe: design/review-2026-11-16/repro/<file>` means the reviewer ran it
    and saved the repro;
  - "Found by reading; not run." means it came from the code alone.

  690 of the 1,059 findings were shown by running a program, and so were all
  nine critical ones. I re-ran three of the critical repros myself
  (x-typecheck-order-01, x-typecheck-patterns-01, f-call-flow-01): all three
  reproduce as written.
- Repros are in `design/review-2026-11-16/repro/` (694 files). Each file's
  header gives the command, what was expected and what HEAD prints. Most run
  as `graphix --no-cache <file>` or `graphix-fuzz check <file>`. A `.rs`
  repro is an integration test: copy it into the named crate's `tests/` to
  run it. The directory also holds probes that no CR cites.
- Duplicates were merged mechanically (same file, a nearby line, a similar
  title); the kept CR says "Also reported as (…)". One root cause reported at
  different sites keeps a CR at each site; the themes below name the
  clusters.
- Drift in `CLAUDE.md` is not written as CRs. It is listed near the end.

## Themes

1. **Unsound typing that reaches the JIT (five critical).** In each the check
   accepts and a kernel panics on a value of the wrong type, or worse.
   - **Written tests in patterns.** A test holding `_` beside a live member,
     or over `Any`, types its bind at bottom (x-typecheck-patterns-01). An
     arm that decides a part of `Any` to be a reference, or an abstract
     type, is tested by tag alone (x-typecheck-patterns-02, -04). A test
     holding a declared variable is not judged at the call that instantiates
     it (x-typecheck-patterns-03, for Eric). Neighbours: t-contains-b-01,
     -02, t-parser-b-01, -02.
   - **Widening.** A call widens a variable of a callee that is not a fresh
     instance, after an earlier argument read the cell narrow
     (x-typecheck-order-01); a widening does not tie an earlier argument's
     open function cells to the new variable (x-typecheck-order-02).
   - **Interfaces.** The interface check accepts an implementation whose
     parameter type is a body-private type of the same name: SIGSEGV
     (x-typecheck-generics-01).
   - **Settling.** An input's end binds a `Concrete` cell to bottom, and a
     later REPL input gets a value outside its type (t-settle-01);
     `lower_into_kept` skips a callee with inferred bounds (t-settle-02).
   - **Cells.** `merge_one` moves lower bounds into an earlier compile
     task's cell unrecorded, so two sibling modules check or fail by
     schedule (t-tvar-a-01, 14 runs of 20 against 6); a conjunct holding its
     own cell is added unchecked and the check runs out of memory
     (t-tvar-a-02); t-tvar-a-03, t-setops-01, t-typ-mod-01, t-rep-01.

2. **JIT state shared across emissions (three critical).** A bind in a
   compile task that does not emit, or a forked bind, numbers its functions
   over the root emission's cached kernels, and wrong code is called
   (f-mod-lowering-01, f-jit-01: one root cause seen from two files). A tail
   loop's rebind of a `_` formal overwrites a capture of the formal's
   declared name (f-call-flow-01). A run-time bind that fuses a multiple of
   `LINK_BATCH` regions never links (f-jit-02). `all()` fuses through a
   helper that compares references by cell (x-builtin-effects-01).

3. **Nodes that did not follow bind-driven bodies and `Tag::MOVED`.** The
   rule is a few days old and these sites predate it:
   - a struct literal keeps a moved field's old value in the node-walk while
     the JIT takes the new one (c-data-map-01, found by three reviewers);
   - `once`, `take`, `filter` and `queue` come back from bottom with no
     event and no moved mark (x-engine-firing-02, lang-skill-01);
   - a banked `~` pays at a wake, which makes a wake an event
     (x-sleep-wake-04, x-seq-sampling-03, x-engine-firing-05,
     c-node-mod-03);
   - a `&mut <expr>` cell is reset to its initializer at every wake
     (c-bind-01: tui's browser and gui's window declare such defaults), and
     a place reference fires where a body first makes it (x-refs-01);
   - a fold's new slot takes its accumulator as a fire (tests-select-a-01,
     f-scaffold-body-01);
   - the map's idle-slot skip ignores a callback a wake moved, so the pruned
     walk keeps the old function (c-prune-wake-01, c-collection-01), and a
     guard's tentative bind fires readers the walk passed
     (c-prune-wake-02);
   - `iterq` and `queue` re-deliver their last element at a wake
     (tests-lang-rest-d-01, collections-str-02); `http::serve` fires a new
     handle at its arm's wake (http-sqlite-db1-03).

4. **Dynamic modules: the 11-15 build's edges.** The name sandbox holds; what
   it grants and what a reload leaves do not.
   - **A sig import is a write grant.** A guest that imports `limit` may
     write it, and one that imports `str::trim` may replace it for later
     loads (a-packages-01, x-refs-05); `use super::NAME` in a block grants
     the whole package's `NAME` (t-env-01).
   - **A loaded body may implement core traits for types it only imports,**
     and the impl is global: the host's maps lose their keys
     (x-dyn-modules-03, x-traits-abstract-01, x-typecheck-generics-02: one
     hole, three reviewers).
   - **Retirement.** A reload leaves a run-time bound instance on the
     retired impl and marks no call site (c-callsite-01, -02, c-lib-01,
     x-dyn-modules-06); a retired load's `Ord` goes while its values live on
     in a host's map (x-traits-abstract-03, x-dyn-modules-05); a reload
     while a seq step's call is pending wedges the seq
     (x-dyn-modules-02).
   - **A crash.** A warm image start under forked evaluation segfaults in
     JIT code when a dynamic module in a collection slot calls a program
     function (x-dyn-modules-01, critical).
   - The sandbox confines names, not resources (a-packages-02): a body of
     operators alone wedges the host. Which audience the feature serves is
     Eric's to say.

5. **A builtin's signature is trusted (a-stdlib-01).** Any script outside a
   dynamic module can bind a registered builtin's marker under a signature
   of its own, and fused code then reads a string as an `i64`. A package
   author's wrong return type fails the same way. The fix proposed is local:
   refuse the marker outside the registering package and audit builtin
   values against their type in `run!`.

6. **queuefn and seq across a sleep or a second run.** A release that lands
   while its site sleeps is lost with its credit (core-aux-01,
   x-async-io-01); a standing argument never reaches the wrapped function
   (core-aux-02); a wrapper called from a seq step answers the previous
   run's result (tests-lib-a-01, x-engine-seq-errors-01). A `~` keeps its
   last output across a step's rebirth, so a later run completes on the
   previous run's sample (c-node-mod-01, x-rerun-6-01). A seqq capture is
   latched on fires and goes stale after a wake or a quiet change
   (x-seq-sampling-01), and one untraceable callee makes every capture live
   (x-rerun-5-01, x-rerun-3-02, x-seq-sampling-05). A step that reads a
   binding derived from a variable an earlier step wrote reads the old value
   (x-seq-sampling-02, for Eric).

7. **Async io against sleep and delete.** `fs::write_all` is declared
   cancel-safe but runs on the blocking pool, so an aborted write can land
   after the write that replaced it (sys-io-01, x-builtin-effects-02).
   Delete aborts evals that sleep lets finish (x-async-io-06, core-lib-01).
   db accessors release the subscription's shared bind id (db2-01, db2-02).
   The GUI's clipboard mutex is held across blocking reads (gui-core-01).
   `array::group` never answers again after its arm sleeps mid-backlog
   (collections-str-01).

8. **Images.** A warm start loses `BodyShared::held`, so a returned
   function's default is "not defined" to a later input or load (c-lambda-01,
   c-image-01); a never-dispatched callee is slept with its arm
   (x-image-01). Labeled defaults are the weak spot of `lambda.rs` generally

9. **Cost.** A collection callback that does not fuse costs a node graph per

## Design assessments

Four reviewers looked at one whole design each, not its lines. Their assessments are printed as written; their findings are CRs like the others (ids `a-...`).

### a-language

**What the design is.** Graphix has one rule at its core: a node fires when an input it consumes fires, every value starts at bottom, and leaving bottom fires. `<-` is the only cycle and lands next cycle; `select` is the only branch and its unselected arms sleep; `seq` lowers straight-line steps to a state machine for anything that must happen in order. Types are structural with unions, inferred, and sound by refusal.

**What is strong and must be kept.** I wrote five ordinary programs as a newcomer would. A poller with backoff as a self-triggering `seq` (16 lines), a retry loop inside a larger ceremony (a recursive function holding a `seq`), a TCP line server (12 reactive lines) and a recursive tree transform all ran correctly first time. Keep: organic firing with no stored selection (it is why both engines can agree); glitch-free cycles in text order; `<-` as the one delay; exhaustive select with dead arms refused; seq as a lowering, not a second evaluator; typed errors with checked `throws`; the low annotation load (47 of 751 `let`s annotated in the 4,378-line admin port); traits v1 with static dispatch (the port uses no trait and no abstract type of its own, so do not build v2 until a module asks); the `cases` fences; the constant-in-arm warning, which was right every time I met it.

**1. Type inference is growing by rulings.** Since the last review `design/tvar_constraints.md` went from 528 to 3,835 lines, the five core files in `graphix-types/src/typ` from about 8.3k to 23.4k lines without tests, and 885 of 2,316 commits touched `typ`. For that weight the check still refuses `compose`, a call of an unannotated function parameter, a field or tuple read of one, and an unannotated recursive function over a variant. The doc says of a cell's two choices that neither is complete without an upper bound. That is your own test for a model in question. I would stop adding refusal rules and spike inference that keeps lower and upper bounds on every variable (MLsub, Simple-sub, MLstruct are the nearest relatives, and they get principal types and order independence, which was given up on 11-13) on a subset, then count the rules it turns into theorems. Cost: a week to learn whether it fits select's narrowing; a rewrite if it does.

**2. An effect's clock is implicit.** A write or an Io call fires when any input fires. That one fact produces the first, second and fifth bite rules. My first form handler, `|c| select valid { .. write_all(..) .. }`, showed an error at startup and saved the file with no press; the check said nothing about `c`. My first table edit spun at 100% CPU, unreported. The port carries about 252 `~` in 4,378 lines. Cheap: warn where a lambda that writes or performs reads none of its named parameters, and log once when a connect loop runs unbroken. Larger: a block clocked to one event in that event's cycle (`on e { .. }`), lowered as a seq block statement already is. Solid's `on()` and FRP's Event/Behavior split answer the same problem.

**3. Arms can only resume.** A re-entered arm shows what its event-consuming nodes held when it slept: tab A displayed `uniq(data)` as 1 after `data` became 2. The 16-row idiom table in `bind_driven_bodies.md` and the advice to build every component at the top level are the price. Synchronous languages give the author both transitions (resume and restart). The seq world already has restart (a step's arm is born at its first selection); offer it as an explicit arm or select. Cost: moderate, the birth view exists.

**4. Seq has two gaps.** It has no step that waits for the next event of a stream: `live(answers)` after a write took the previous reply, and only the undocumented `live(once(answers))` worked. And its value arrives a cycle after its trigger, so it cannot be a handler that answers its event, which is why handlers stay hand-sampled. No TUI or GUI example uses seq.

**5. Failures are quiet.** In a default run a fused division by zero, a `$` drop and a seq stalled on it print nothing; `--no-fusion` reports the division only; drops need `RUST_LOG` and `--log-dir` together. Every debugging knob serves compiler developers. "Nothing happened" is this language's main failure, and authors have only `dbg`, which is silent exactly then. Report from the kernel's cold path, honour `RUST_LOG` alone, and add a per-binding `--trace`.

**6. Small things reached for first.** `x == null` is refused and the message names no fix; arithmetic on a nullable advises a cast where `$` is meant; `array` has no `reverse` or keyed sort; `t@ 1` cannot be written though the warning tells you to sample the bind.

**Inherent or debt.** Inherent to reactive dataflow: `<-` next cycle, backward readers a cycle late, a seq's value bottom until its first run, state that tracks its initializer. Debt with a fix: sampling in handlers, the self-loop, whole-input sampling, constants and components in arms, replies lost to arm sleep, the three snapshot worlds leaking through `live`. A consequence I would accept: a level filtered from an event dies with its arm (61 `_ => never()` sites in the port), since the alternative is stored state in select.

**Relatives.** Lustre and Esterel put clocks in types and make `pre` the only cycle; Graphix matches the second and lacks the first. Elm and Bonsai run effects only from event handlers, at the cost of boilerplate Graphix avoids. Rx glitches where Graphix does not.

### a-compiler

WHAT THE DESIGN IS. One front end (graphix-types, 85k lines: parser, types, checker, env, image session) feeds a node graph that is both the IR and the interpreter (graphix-compiler: 41k lines of nodes, 25k of fusion). Pure subtrees are replaced by cranelift kernels, and a differential fuzzer (22k) holds both engines to one answer across cold, warm, forked and pruned runs. graphix-rt (4k), the shell (3k) and the language server (3.5k) are thin and sit on it cleanly.

WHAT IS STRONG; KEEP IT.
- The node graph as the only IR, with strict fusion. I put 20 ordinary pure idioms under #[native] (structs, unions, nested folds, recursion, interpolation, `$`): all 20 fused whole. The three I expected to be refused (`array::sort`, `any`, `~`) were, each by name. The split of what fuses is stable and fits in one sentence. Pinned fuzz findings by month, July to November: 84, 97, 38, 16, 21. Only 148 of the 2,315 commits since the last review touched fusion/. The two engines are no longer where the bugs are.
- What the types hold. Compiling cannot reach the runtime (`CompileCtx` against `ExecCtx`). `CompileCtx::fork` and `join` name every field, so a new field cannot be forgotten at a fork. `NodeView` and the exhaustive `node_facts`. One `with` constructor per node, shared by compile and image decode. Test-only step counters that pin algorithmic cost.
- Images written by the binary that reads them, keyed by build id. About 500 hand-written encode/decode functions (6,000 lines) is a real tax on every node kind and builtin, but it removes every producer/consumer mismatch and buys a tenfold faster start. It pays.
- The audit modes (PAR_AUDIT, PRUNE=audit, QUIET=audit, ELAB_AUDIT): each optimization's invariant becomes a crash the fuzzer can find.

WHAT A FEATURE COSTS. One ordinary node kind (ArraySlice) is named in 12 files, 22 times outside its own: the AST variant and child enumeration, seven printer arms, the parser, compile dispatch, NodeView, NodeTag and decode dispatch, two analysis matches, its emitter, the fuzzer. Most are compile errors when forgotten. The silent ones are `sleep` and `delete` for a kind with state of its own, `fuse` (fusion is lost below it) and the access summary (finding). A builtin is four places (the struct by macro, the defpackage! list, the .gx, the .gxi); forgetting one fails the stdlib's check, and a wrong EFFECT is the silent one, as documented.

THE PROBLEMS, IN ORDER.

1. The type checker is where the design is under strain, and it is the one component with no second opinion. 885 of 2,315 commits touched typ/, and 1,333 touched the check (typ/, callsite, select, lambda, tvar_constraints.md). `contains` runs under eight mode bits, with three functions that translate one combination into another. A cell has 13 fields. The rule book is 37,450 words with one 3,445-word paragraph. By your own test (many corner-case rulings on one mechanism), the model is in question. I would not reopen argument order. I would: make the walk's modes a sum type; turn the rule book into a model plus a table of rules, each with a checked `cases` line; and add the two missing oracles. The fuzzer does not hold values to their static types though `run!` does (about a day). The reflective oracle is unbuilt, waiting on one ruling. Cost: one to two weeks. It buys the ability to change a rule and be told what broke.

2. An instance is a recompile, and the node-walk needs one per element. A callback that does not fuse costs a compile and 4 to 11 KB per element. Filtering 400,000 lines through `re::is_match` peaks at 3.0 GB and 33 CPU-seconds, against 97 MB and 1.2 s for `str::ends_with` (debug binary; the docs pin 3.2 KB a slot). Fifteen `Stateless(None)` builtins (parse, regex, the sorts, the writers) put ordinary data loops on that path, with no warning. I would run one instance over the elements when the body is pure and keep per-slot instances for bodies with state: about a week, plus a soak. The deeper fix (each node split into a shared template and per-instance state) I would not start: it was tried, and images now cover start-up.

3. seq kept what bind-driven bodies deleted. `TrackedFires` and `CatchUp` (wake.rs, 795 lines) hold fire bits, clocks and learned sets for the seq world. The language now has two rules for missed fires, chosen by whether a select is written in a step or in a function the step calls. This needs your ruling: is fire memory for `live(e)`, nested triggers and learned inputs worth the second rule?

4. `R: Rt` and `X: GXExt` have one production instantiation each, yet are written on 1,113 lines. 23,572 functions (14.7% of the binary's text) can only be compiled downstream. Erase them. The edit is mechanical, wide, and an API break for netidx-admin; do it when the tree is quiet.

5. Smaller. The access summary's open default breaks NodeView's promise. `Control` carries the evaluation pool and test counters into the "static half". Stale `wake catch-up` comments. CLAUDE.md says `Update` requires methods that in fact default.

WHAT I WOULD NOT CHANGE. The two engines and the fuzzer; strict fusion; images; the deferred-runtime rule; argument order (ruled); scoped thread-locals for ambient state (each is set and read on one call stack).

ORDER. (1) The is_a oracle in the fuzzer and an exhaustive `own_access`: days, pure gain. (2) Walk modes, the rule table, the reflective-oracle ruling. (3) Pure callbacks on one instance. (4) The seq ruling. (5) Remove the runtime type parameters. (6) Split `Control`.

NOT MEASURED. Build and test time: cargo was off limits to reviewers. Every timing is the debug binary's, so read the ratios, not the absolutes.

### a-stdlib

**What I reviewed and how.** I read every `.gxi` (about 520 `val`s in 5,000 lines, about 350 registered builtins in 20 packages), the builtin traits, the design docs the assignment names, and wrote six programs: a directory of JSON files validated and summed into a TOML report (22 lines), a tcp line server over sqlite (39), a TUI with a table, a form and a status line (70, driven through a pty), the same screen in the GUI (45, checked only), a command capture (8) and an http server with its client (14). The evidence is in `design/review-2026-11-16/repro/a-stdlib-*`.

**What the design is.** Signatures are Graphix (`.gxi`); bodies are Rust reached through a `'name` marker. A builtin is written at one of four levels: `fast_builtin!` (114: one function, one macro line), `EvalCached` (14), `EvalCachedAsync` (52), a raw `Apply` (45). Collections are Array, List and Map with traversal as compiler nodes, plus a `Collection` trait. IO is one stream model: a type per stream kind and traits for what it can do. Data comes in through type-directed reads. A widget is a struct of references built by a function with labeled defaults, and both UIs decode it with `graphix_rt::props!`.

**What is strong and should be kept.** The server ran right the first time (three clients, twelve commands, replies in order) because `seqq` and errors-as-values did the sequencing. The stream traits are right: a socket, a file and a pipe are the same code, and a write to stdin is a type error. The effect classes fail safe: the default is `Async`, and a `FastFn` is a plain function pointer, so a "pure" builtin cannot hold state. The `Concrete` refusal named the exact annotation a read needed. A widget is cheap (button: 78 lines of Rust, about 25 of Graphix), and `form`, `browser` and `line_edit` are written in Graphix, so composites need no Rust. Packages are cargo features already: I would split nothing out.

**Problems, most important first.**

1. *A builtin's signature is trusted, and anyone may write one.* Any script outside a dynamic module can bind a registered builtin under a signature of its own. Fused code then reads a string as an i64 (a heap address, where the node-walk bottoms) or aborts the process. A package author's wrong return type fails the same way. Fix: refuse the marker outside the registering package, check a scalar fast call's kind as the Value path does, audit builtin values against their type in `run!`. Days.

2. *Typed reads are closed over fields, loose over scalars, late and mute.* `json::read` into `{name, qty}` refuses a document with a third field (so do `toml::read` and `sqlite::query` over `select *`), accepts `"qty": "5"`, names no field in its error, and answers a cycle after its text: it rides sqlite's async reader with nothing to await, so a reply printed beside its parsed body shows the previous body. This is the reading interface for every REST call and config file. I would have the readers take the named fields and drop the rest (`#strict` for today's behaviour), name the path in errors, and make the text readers synchronous like `str::parse`. The cast change is one arm; the timing change needs a soak.

3. *A collection callback's state is positional, in a Map too.* Remove key `a` and `b` inherits `a`'s state. A set of live things cannot shrink, so my server's connection array only grows. Either key Map slots by key and give arrays a `#key`, or give `sys::tcp` a `serve(#handler)` as `http::serve` and `net::rpc` have, on the `Handler` they share. The second is small and covers the main use; the first is a semantics ruling.

4. *A stream's end is not an event.* `Lines::lines` says nothing at EOF, where `Read::read` gives empty bytes and a db cursor null. "Sum the file, then report" has only an idle timer to wait on.

5. *Siblings follow different conventions.* 18 of `str`'s 31 functions take the operand as a required label with the subject last; array, list, map and opt take the subject first, positionally. The first five `str` calls I wrote were refused. `list::take(n, l)` sits beside `list::nth(l, n)` and core's `take(#n, e)`; `fs::write_all(#path, ..)` beside `read_all(path)`; the "do it again" argument is `trigger`, `#clock`, `#trigger` or `#update`. Errors are 37 tags that each carry one string (six spelled `Err`), so a program can catch an error and cannot tell a missing file from a denied one; `sys::time` alone answers a bad argument three ways. One rule each, applied in one pass while there are no users: `str` and `re` have about 60 call sites in both repos.

6. *Gaps, and one cliff.* Of 128 names I guessed, 3 exist. The ones that matter: no `array::reverse`, `contains`, `is_empty` or sort by key (list has three of them), no `map::keys`, `values` or entries, no environment variable, no datetime formatting or parts, no `re::replace`, `math` is f64 only, and `sum`/`product`/`divide` return a `Number` no operator accepts. Accumulating with `array::push` in a fold is quadratic (64,000 elements: 22 s against 0.1 s for `list::cons` and `to_array_rev`, debug build), and nothing at `push` points to the other way.

7. *The Rust side of a builtin is tied to its signature by hand.* Arguments are read by literal index (about 150 reads here, 70 in netidx-admin, whose ceremonies do index arithmetic against label order), error tags are strings (`queuefn` can answer a tag its signature does not hold), and the signature is written twice, in `.gxi` and `.gx` (430 bindings). Resolve indexes by name from the `FnType` at `init`, let a binding take its types from its `val` as an impl method already takes its trait's, and the audit of item 1 covers the tags.

Smaller: interpolation and `cast<string>` write datetimes and durations differently and `cast` reads only its own form; `use Collection::*`, the glob the book teaches, takes core's `filter` away, and `Collection::map` over a Map sees values where `map::map` sees pairs.

**What I would not change.** The four builtin levels and the effect classes; streams as types with traits; traversal as compiler nodes; widgets as structs of references with `props!`; errors as values with `$` and `?`; one cargo feature per package. One friction belongs to the language review: my first TUI handler wrote `items <- array::push(items, x)` unsampled, the check said nothing, and the list grew on its own.

### a-packages

WHAT THE DESIGN IS. A program is a tree of modules (`mod`, Rust-2018 `use`, an optional `.gxi` interface per module). A package is a Rust crate (`defpackage!`, Graphix source packed by build.rs) compiled into the shell; `graphix package` edits packages.toml and rebuilds the binary from the shell's crates.io source. A dynamic module loads source at run time under a `sig`, whose imports are all its body sees. An embedder gets a runtime on its own thread behind `GXHandle` and a batch channel. The developer loop is `--check`, the session image, `fmt`, the LSP and the REPL.

STRONG, KEEP. (1) The module system's invariant (resolution is a function of module and name, no ambient search) and the interface as the only thing siblings see: it is what lets module checks run in parallel, and it held at 5.7k lines in netidx-admin. (2) The image cache: keyed by build id, flags and modpath, re-verifying every file resolution touched, ISA and fingerprint in the header, never a partial image. I found no way to make it wrong from the outside. (3) The loop is fast: even the debug binary checks a trivial script in 0.10 s cold and 0.04 s warm, and the largest book example in 0.09 s; the ledger has 5.4k lines compiling in 455 ms release, 65 ms warm to first byte. (4) The formatter's reparse guard and the LSP answering from the last successful check. (5) The package manager's failure handling: packages.toml written only after a successful build, the binary replaced by rename with a dated backup, a second copy of the compiler in the graph refused, the skeleton's versions and build pinned by tests. (6) The builtin ladder: 120 `fast_builtin!` uses against 43 raw `Apply` impls in the stdlib; the easy path is the common one. (7) Packages as crates for anything with Rust in it: native speed, no ABI, cargo's resolver, and the build id as cache key all come free. I would not add a plugin ABI or wasm.

PROBLEMS, IN ORDER.

1. A sig import is a write grant (bug, ran). A guest whose sig says `use super::limit` sets the host's `limit` to 99; one granted `use str::trim` replaces `str::trim` for a guest loaded after it. Only a function an earlier compile bound statically is protected. Refuse `<-` and `&mut` on imported names at the load; a host that wants a guest to write passes a `&mut`. Cost: one local rule and its pins.

2. The sandbox confines names, not resources, and the book does not say so (ran). A body of operators alone, importing nothing, wedges the host forever with a tail loop; its non-tail twin passed 6 GB. Budgets are unlimited by default and stop the runtime, not the load. Cheapest: say in the book that a sig is for code trusted not to hang the host. Real fix: budgets charged to the load (`Scope::load` already names it), failing the load into its status. That is a JIT back-edge check and a per-load count: weeks, and only worth it if hosting untrusted code is a goal. Eric should decide which audience the feature is for.

3. The reload model is the mechanism with the most rulings. That a function saved from a module outlives its load with that load's bindings, imports, traits, impls and types costs about 350 of module_system.md's 1096 lines, 47 tests, 88 of the last 2316 commits, and is unsoaked, for a feature no program in either repository uses outside tests and the book. It also means a host cannot fully unload a guest. Consider retiring a load whole: its nodes go, a saved function bottoms and logs. Lost: a saved callback surviving a reload. Gained: `LoadedBody`'s kept state, joins, `KeptImpl`, `impl_reads` deleted.

4. An interface is not an annotation (ran). `val x: [i64, null]` over `let x = 3` is refused until the let restates the type; about 20 of netidx-admin's 35 Graphix-implemented vals restate one. The after-the-fact match (`sig_matches`, `sig_bounds`) is a second subsumption judgment with 220 lines of rules and a documented incompleteness. Give the implementing let the val's type as its annotation. Related: every builtin's signature is written twice by rule, about 420 pairs in the stdlib and 74 in netidx-admin; let the binding take the val's type.

5. Graphix source reaches a shell only through cargo. A library with no builtin still needs a toolchain and a fat-LTO rebuild (the installed binary here is 106 MB) on every machine; a `.gx` edit in a package needs the same rebuild to run; a modpath directory is unversioned and is not a package root. Add a source tier (manifest, resolver-served, covered by the image's probes) and a `--package-src` override. Cost: a manifest format and a resolver; no change to the compiler.

6. No lock for third-party packages. Each rebuild resolves them and their private dependencies afresh, so adding `b` can change `a`, and package code and build scripts run with full authority. Keep the resolved Cargo.lock beside packages.toml. Small.

7. Embedding surface carries an unused extension point and coarse confinement. `GXExt` has one real implementor and 290 bounds in 67 files; delete the parameter. (`Rt` also has one implementor, 1113 bounds, but it is the seam that keeps tokio out of the compiler: a separate decision.) An embedder confines a script only by package set: any script reaches any registered builtin by marker (ran), and `sys` bundles timers and exit with files, sockets and processes. Split `sys` or filter builtins at registration. Hard today and probably fine: stepping cycles synchronously; bounding memory.

BEFORE A STRANGER BUILDS SOMETHING REAL, IN ORDER. Fix 1 and state 2's trust model. The lock (6). The `#[native]` chapter, still open in the ledger and absent from the book though it is the advertised performance model. An install page that offers the release workflow's binaries and says `package add` needs a toolchain. The source tier and dev override (5). A statement of which builtin API is stable (`fast_builtin!`, `CachedArgs`, `CachedArgsAsync`) and that raw `Apply` moves with the compiler; the skeleton should lead with `fast_builtin!`. Then 4, which every multi-module program pays daily but none is blocked by.

WOULD NOT CHANGE. Crates for Rust packages; build-id keyed images; `.gxi` as the module boundary; statement-position declarations; settling each REPL input alone (a pasted `let e = []` then `e <- [1]` is refused, with a message that names the fix: a conscious cost); containment stopping the runtime rather than a credit system for trusted programs.
