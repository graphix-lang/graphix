# Project status — 2026-08-30

A whole-project snapshot taken at the end of the recursion / traits /
select-simplification arc. Facts first, then my read, then what I would
do next. Written for Eric; the numbers are as of this morning's tree
(`01388ab8`).

## 1. Where the project stands, in one paragraph

Graphix is a reactive dataflow language with a full modern type
discipline (structural types with inference, ADTs, pattern matching,
Rust-2018-style modules, nominal abstract types, Rust-style traits with
static dispatch and a constructor-trait hole for higher-kinded
`Collection`), two execution engines (the canonical node-walk and a
cranelift JIT) that are held bit-identical by a six-box differential
fuzzing fleet, twenty stdlib packages, a TUI and a GUI toolkit, an LSP,
a tree-sitter grammar, a package manager with standalone builds, and a
13.7k-line book with 120 examples. The compiler is 68k lines of Rust,
the stdlib 72k, the fuzzer 15k. The language semantics have been
through five weeks of deliberate simplification and are converging: the
fleet's yield fell from 6 findings/day (aug27a) to 1 in 17 hours
(aug29a), and that one is a harness heuristic, not an engine
disagreement. The last release, 0.9.0, was on 2026-05-08 — 860 commits
and every one of the arcs below ago.

## 4. Open threads, by area

Ordered by how much I think each one matters, not by area.

### 4.1 Correctness (the only things that can be WRONG)

- **aug28a aieka/000000 — fold-in-guard / `array::group`** (parked
  2026-08-28, well-typed, re-verified on the fixed binary). A reactive
  program where `array::iter` streams, a `let rec` base case is a
  guarded select over an `array::fold`, and the result feeds
  `array::group`: interp emits nothing, JIT emits `[2:[2,2,2]]`. This
  is the ONLY open interp≠jit disagreement in the pipeline and it has
  sat for two days under the ride arc. Needs adjudication against the
  intended semantics (organic firing + bottom-out), not against either
  engine. Re-checked on HEAD today — see §6.
- **The last three rulings are young.** Ride deletion (08-29) has one
  clean 17-hour round; recursion shrink = delete (08-29) has zero —
  aug30a is its first soak. "Gates are not the fuzzer": neither is
  landed until it has a quiet round-day behind it.
- **Typemorph residue**: 5 corpus flips in the extract-annotate
  bucketing class await a rule from Eric (the P2 open item
  "body-annotation tvars are fresh, not the signature's"). Acceptance-
  plane only; nothing runs wrong.

### 4.2 Performance predictability (Eric's stated core value)

- **Fusion residue** (coverage, never correctness — by construction):
  union-self trait dispatch de-fuses; abstract patterns in select
  de-fuse; arm-lifted connects inside loops/callees de-fuse;
  loop-carried Value rebinds (`lfold_rec`); String-returning
  cross-kernel callees; whole-composite/`@`/named-rest binds; decimal
  arithmetic. Each is pinned by an ASPIRE fixture or a `#[native]`
  de-fuse test. (Trait default bodies and fn-formal forwarding/capture
  FUSE since `b386f97d`, 2026-08-27 — I had this wrong in the first
  draft; corrected after re-measuring on 08-30.)
- **Interp cost is the floor for everything above.** Per activation
  ~8µs / ~15KB (release); a stdlib-shaped recursion runs ~60x behind
  the intrinsic on the interp even after the loop-invariant-formals
  cut. The node-walk is the fallback for every unfused shape, so 4.2's
  two bullets compound. (Later on 08-30: a nested HOF inside a callback
  was found QUADRATIC on the node-walk — the `LambdaIds` hub — and
  refused fusion as spurious mutual recursion; both fixed the same day,
  `bench/collection/README.md`.)
- **Intrinsics endgame** (bench/collection re-swept 2026-08-30): at
  parity and deletable today — Array `map` (two derivations), Array
  `filter` (via `filter_map`), Map's whole impl (already Graphix
  wrappers). Not yet: `fold` itself (a hand-written loop pays ~50x in
  per-element `len`/`a[i]$`/callback call overhead — the cost any user
  impl pays), `find`/`find_map` (the Option-carrying fold fuses but
  can't early-exit, 2.4x), `flat_map` (fold+concat is O(n²) by
  construction), and List (loop-carried Value rebinds keep an
  activation per level). This is compiler simplification, not a
  user-facing gap — except the ~50x, which is what a user's own
  `Collection` impl runs at.

## 5. My read, and what I would do next

The five-week arc did what it set out to do: the semantics are simpler
than they were in July (no stored selections, no rides, no depth
limits, no per-eval-per-cycle recursion), the type system grew the two
features (traits, constructor traits) that let stdlib functions be
written in Graphix, and the fleet says the two engines agree on all of
it. What the project does NOT have right now is a user who is not us:
nobody outside can run this language, and the one program that
exercises it as a user would (the admin TUI) has been on hold for nine
days.

So I would stop changing semantics and consolidate, in this order:

1. **Let aug30a soak** (2–3 quiet round-days) and, while it does,
   close the last correctness item: adjudicate aug28a's fold-in-guard
   class, and fix the harness discriminator so the fleet stops
   reporting slowness as a wedge. Fix the two stale design-doc status
   lines. No new rulings.
2. **Cut 0.10.0.** Draft the CHANGELOG from the 860 commits by arc (I
   can produce the draft; the table in §2 is its skeleton), run the
   slow-tests gate in release, bump, publish. The published binary and
   the published book should agree. This is the largest external-
   facing gap and it is cheap.
3. **Resume the admin dogfood at Phase D.** It is the only source of
   the next class of language problems, and the compiler arc it
   triggered is done. Its open prerequisite is terminal suspend/resume.
4. **Fusion residue and the intrinsics endgame in the background**,
   driven by what the dogfood and the benches actually hit — the
   per-element call overhead of a hand-written loop first (it is what
   every user-written `Collection` impl pays), then the carried-Value
   rebind for List. Traits v2 only when a real program needs it.

The alternative ordering — dogfood before release — is defensible if
Eric expects Phase D to change the language again the way finding 1
did. I would still release first: a pre-1.0 minor is cheap, four
months is long, and the fuzzer's flat yield says this is the quietest
the tree has been since the fusion merge.
