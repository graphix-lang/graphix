# Code review — 2026-10-05

Scope: the whole repository at `c722befe` (main): every tracked source file,
tests, the stdlib's Graphix sources, examples and the IDE tooling. `../netidx`
was out of scope except where Graphix reaches it.

## How to read this

- Every finding has an id (`c-callsite-01`, `t-tvar-03`, …). Its CR in the code
  ends with that id: `// CR claude for eric: [tag] text (id)`. Find them all with
  `grep -rn 'CR claude for eric'`.
- Tags: `bug` (wrong behaviour reachable today), `risk` (a hazard not yet shown
  reachable), `structure`, `style`, `readability`, `perf`, `dead`, `doc-drift`,
  `test-gap`.
- Repros: `design/review-2026-10-05/repro/<id>.gx` (some are `.sh`, `.py` or
  `.rs`). Each has a header with the command, the expected output and what HEAD
  prints. Most run as `graphix --no-cache <file>` or `graphix-fuzz check <file>`.
- Drift in `CLAUDE.md` and defects in `../netidx` are listed at the end of this
  document instead of being written into those files.

## How the review was done

The tree was cut into 75 units of about 2–3k lines. One reviewer read each unit
line by line. 20 more reviewers each took one concern across the whole
repository:
- adversarial semantic probes for firing, collections and seq/errors;
- type-checker soundness;
- images, stack depth, unsafe code and panics from external input;
- the node trait contract, builtin effect classes and parallel evaluation;
- diffs of the last week's arcs;
- doc drift, duplication, allocation and invalid states.

Every correctness finding then went to its own verifier. The verifier tried to
refute it and to reproduce it by running a program against the debug binaries
at HEAD. Minor findings were vetted per unit for accuracy and value. A third
agent re-ran every critical and high repro and compared the output with the
repro's header. Duplicate reports were merged before verification. Several
defects were found independently by two or three reviewers.

Nothing in the tree was changed except the CR comments, this document and the
repro directory.

## What matters most

The review found real defects at a high rate. Almost every verified finding was
reproduced by a program, and none of the re-executed critical/high repros failed
to reproduce. The themes below group the critical and high findings. The tables
further down list everything.

### 1. Type soundness holes that reach the JIT

Several typing rules let a well-checked program store a value of the wrong type.
The fused code then trusts the type and panics, segfaults or computes garbage.
- **References are covariant though writable.** `c-node-mod-01` (contains.rs).
  On top of that, unions of references merge into one reference: `t-fntyp-01`
  (normalize.rs). So `let r: &[i64, string] = &x; *r <- "boom"` writes a string
  into an i64 and the JIT panics. References must be invariant, and `&A ∪ &B`
  must stay a union.
- **Reference type tests ignore the referent and accept any u64.** That forges
  typed writes. `x-typecheck-patterns-01` (cast.rs `is_a`). The type-directed
  reads (`str::parse`, `json::read`, `pack::read`, `net::subscribe`) also accept
  `&T` targets and forge references: `x-typecheck-generics-F14`. The same reads
  forge error values: `small-pkgs-04`.
- **Values that share a runtime representation are not told apart.** List vs
  Array vs 2-tuple, `` `A `` vs `"A"`, variant vs tuple. Type tests, `flat_map`
  splicing and union trait dispatch pick the wrong arm or splice the wrong value.
  See `x-typecheck-patterns-04`, `c-collection-01`, `t-cast-setops-04`.
- **Rigid and rank-2 type variables leak.**
  - A rank-2 quantifier escapes through a captured cell: `x-typecheck-generics-F6`.
  - A quantifier named like an outer variable shares its cell: `-F9`.
  - Rigidity is enforced only on a formal's whole type: `t-fntyp-03`.
  - A declared variable loses rigidity through a name alias: `-F13`.
  - `bind_ctor` lets an open rigid constructor variable through: `t-tvar-01`.
  - An occurs-check refusal is read as containment: `t-tvar-08`.
  - `⊥ ⊇ 'x` binds a parameter to ⊥ and the gate reopens it: `t-tvar-02`.
- **Union normalization equates distinct unbound type variables** inside
  products: `t-fntyp-02`. `sig_matches` does the same: `t-fntyp-04`.
- **Patterns.**
  - Slice rest, `all@` and element binds are typed narrower than the scrutinee:
    `c-pattern-01`.
  - Or-pattern payload types are never checked: `c-pattern-03` to `-06`.
  - A nested fn type in a type test is not refused: `x-typecheck-generics-F5`.
  - The literal pool aligns leaves by flat index and ignores type predicates, so
    it accepts non-exhaustive selects: `c-select-seq-02`, `x-typecheck-patterns-02`.
- **Labeled defaults** narrower than a function type the value is passed as are
  never checked. The JIT gets an i64 where it expects an f64:
  `x-typecheck-generics-F7`.
- **A conjunct probe** admits a rigid rhs cell and leaves the lhs open:
  `t-contains-03`.
- **Writable bindings are generalized:** `t-tvar-03`. **Dynamic module bodies
  compile at the generic level:** `t-tvar-04`.

### 2. The check and the build disagree

Many programs pass `--check` and the LSP but fail elaboration, or the reverse.
This is the class `GRAPHIX_ELAB_AUDIT` exists for, and it is wide:
- trait calls over a primitive-union self: `x-engine-seq-errors-04`;
- impls or trait bodies with bounds the trait omits: `x-diff-types-01`;
- builtins whose `typecheck1` refuses what the check accepted: `x-builtin-effects-08`;
- defaults checked in the wrong environment: `c-callsite-04`;
- `flat_map` over nested arrays: `x-engine-collections-02`/`-03`;
- `$` over an open cell: `x-typecheck-generics-F1`;
- impls inside lambda bodies: `c-module-traits-05`;
- `--check` placing a script at `/` while the run uses `#do`: `t-typ-mod-04`.

Run-time binds that fail their typecheck are logged and run anyway
(`x-typecheck-generics-F10`), which turns any such gap into a runtime one.

### 3. Firing, sleep and wake

Both engines get several cadence rules wrong.
- **A select's no-arm window** (bottom or undecidable scrutinee) neither updates
  nor sleeps the held arm. Timers die and seq runs wedge: `c-select-seq-01`.
- **Restart and async builtins misbehave across sleep.**
  - Async builtins and `range` never restart after a wake when their arguments
    are standing values: `x-engine-firing-04`.
  - `take`/`skip` lose `#n`: `-05`.
  - Builtins that keep their output across sleep re-emit it at wake: `-07`.
  - Pure builtins classified `Sync` show pre-sleep values at wake: `-06`,
    `x-builtin-effects-07`.
- **Writes through references.**
  - A binding written only through `*r <-` is not a connect target, so a wake
    resets it: `c-node-mod-02`.
  - `ConnectDeref` keeps a stale target across sleep: `c-node-mod-03`.
  - Every retarget re-writes the last value into the new place:
    `x-engine-seq-errors-09`.
- **Wake catch-up.** The catch-up bit is spent with no delivery when the input
  was republished STALE: `c-select-seq-03`. Wake phantoms replay as real fires:
  `c-bind-07`.
- **`seqq`.** Capture liveness is keyed by the seq's expression id, so a
  definition's instances overwrite each other: `c-analysis-branch-01`.
  `flush` drops a same-cycle request: `x-engine-seq-errors-06`.

### 4. Fusion and the JIT

- **A native tail loop shares one activation's kernel memory across passes**:
  `f-call-flow-03`. A self tail call doesn't widen a scalar into a union
  formal: `f-call-flow-01`.
- **The callee context word drops the wake bit**, so a woken arm's fused callee
  fires on stale arguments: `f-kernel-01`.
- **`FusedKernel` is classified Async**, which flips a pure arm to sleeping:
  `f-kernel-02`.
- **Placeholder emission** for always-bottom `?`/`$` produces Value-shaped
  payloads in scalar code, and the link panics: `f-call-flow-02`.
- **Loops over a bottom source** run the placeholder's length: `f-scaffold-body-01`.
  A new slot's init view leaves outer reads stale: `-02`.
- **The option-form type test** matches any non-null value: `f-select-03`.
  **A pure guard's literal fire is dropped**: `f-select-01`.
- **`expand_refs` keys its memo on a freed address:** `f-mod-lowering-01`.
- **A JIT that cannot be built fails every compile** instead of falling back:
  `f-mod-lowering-05`.

### 5. Parallel evaluation

- **`ORDERED` is honoured only by block plans.** `queuefn` calls in forked
  fields, arguments, operands and collection slots race: `x-parallel-01`,
  `c-collection-02`. Fields, arguments, operands and slots fork with no
  independence check: `c-analysis-branch-03`.
- **Closures and references sort by ids minted in parallel**, so the order
  varies run to run: `x-diff-par-02`.
- **Core-trait dispatch is invisible to dependency summaries:**
  `c-analysis-branch-02`.
- **The fuzzer never exercises these paths.** It never runs `Auto`'s fork
  shapes, `JitPar` or `Pair::Check` on its batch path, or a fork over an image:
  `c-cost-misc-05`, `fuzz-main-aux-02`.

### 6. Session images

- **The program image key covers only the root file.** An edited module runs
  stale code and masks errors: `x-image-01`.
- **No integrity check.**
  - A corrupt entry runs wrong, crashes or executes corrupt machine code:
    `x-image-03`, `-05`.
  - `decode_at`'s cycle check is defeated, so a corrupt image recurses until
    memory runs out: `x-image-04`.
  - A failed read poisons the id allocator: `x-image-06`.
  - An unreadable entry is never replaced: `x-image-07`.
- **Cold and warm runs differ.**
  - Lazily restored instances register no reads: `x-image-02`.
  - Expression sharing ignores decorations, so `#[parallel]`/`#[serial]` is lost
    when warm: `t-image-01`.
  - The registration image drops `LambdaIds` links: `x-builtin-effects-09`.

### 7. Robustness against input

- **Stack overflows (process abort):** deep `json`/`toml`/`hbs` values
  (`x-panics-07`), abstract-value walks (`x-stack-02`), module resolution
  (`x-stack-04`).
- **Panics:**
  - the duration parser in `../netidx` (`x-panics-01`);
  - LSP paths with `[ ] ^ |` (`x-panics-03`) and an LSP with no panic guard
    (`x-panics-02`);
  - formatter config (`x-panics-13`);
  - intransitive user `Ord` in sorts (`collections-str-02`);
  - canvas NaN, and zero text size in the GUI (`gui-widgets-a-01`, `-02`);
  - several TUI widgets (`tui-widgets-02`, `-03`).
- **The checker hangs or OOMs** on growing-parameter recursive types:
  `t-contains-09`, `t-cast-setops-03`, `x-parallel-02`.
- **Dynamic-module sandbox escape:** a host builtin defined inside a lambda
  body escapes the sandbox (`c-module-traits-01`).

### 8. Standard library

- **http.** `http::serve` pairs any handler fire with the oldest request, so
  responses leak across clients: `http-sqlite-db1-01`. One unanswered request
  wedges the server (`-02`). A TLS handshake blocks the accept loop
  (`x-panics-09`).
- **`sys::net`.**
  - Error deliveries are cast to the success type, so failures read as 0:
    `sys-net-01`.
  - A failed remote write reaches the callback as an error and the JIT panics:
    `-02`.
  - One unanswered rpc wedges the server: `-03`.
  - Writes are lost after an arm sleeps: `-04`.
- **`sys` io.** A pending read holds the stream's only lock: `sys-io-01`. Watch
  readers steal each other's events (`-04`). `wait()` defeats `kill_on_drop`
  (`-07`). `lines()` latches its first stream (`-08`).
- **db.**
  - A transaction holds sled's global write lock across cycles: `db2-01`.
  - Internal tree names bypass the type metadata: `db2-02`.
  - Keys are not order-preserving for floats, datetimes and tuples:
    `http-sqlite-db1-03`.
  - Subscriptions go deaf after sleep: `db2-05`.
- **json/toml/pack.**
  - Parse errors are cast into values, so garbage reads as 0: `small-pkgs-01`.
  - Map keys are written through `Display`: `small-pkgs-03`.
  - Lists are written as cons cells: `x-stack-06`.
- **Graphix stdlib.**
  - `Read::read_all`/`read_exact` defaults keep stale state: `gx-stdlib-01`, `-05`.
  - `sum`/`product` keep the old total over an emptied array: `gx-stdlib-06`.
  - `opt::map` emits `f(stale x)`: `core-aux-01`.
  - `radio.gxi` uses an undeclared type variable the checker accepts: `gx-ui-01`.

### 9. Lifecycles and leaks

Compile-time registries only grow:
- `lowered_seqs`: `c-lib-01`;
- `batch_connect_targets`: `c-lib-02`;
- def assertions under `CheckOnly`: `c-lib-03`.

The LSP leaks per keystroke. At runtime, delivery ids, `ByRef` cells and timer
ids are never released (`x-node-contract-05`/`-06`, `c-bind-11`). `queuefn`
leaks every instance (`core-aux-03`), and abandoned async work is never
cancelled (`rt-01`).

### 10. Tests and the fuzzer

- **`run!` is weaker than CLAUDE.md says** (`core-aux-13`).
  - It checks each mode's result against the fixture's predicate rather than
    comparing modes with each other.
  - Its serial `interp`/`jit` baselines now run under `Auto` and may fork.
  - The JIT mode is compiled out of release test builds.
- **About 80 fixtures accept any `Err`.** A parse error or a compiler panic that
  kills the runtime passes them: `tests-lang-b-06`, `tests-lang-d-05`.
- **The fuzzer's oracle treats some failures as agreement:**
  - a Timeout beside an eventless trace (`fuzz-main-aux-05`);
  - a child killed by the 8 GB address-space cap (`fuzz-main-aux-06`);
  - `-0.0 == 0.0` (`fuzz-main-aux-20`).
- **Soak campaigns** ignore their base seed (`fuzz-gen-a-01`) and drop crashing
  subjects (`fuzz-main-aux-01`).
- **Several pins cannot fail:**
  - `check_mode_parity`;
  - `deep_nesting`'s modnest shape;
  - `interrupt_wedge`'s later-cycle case;
  - the GUI `*_renders` tests.

## Structure and readability, in short

The minor findings that survived vetting cluster in a few places:
- **Duplication.** Fast-builtin boilerplate is hand-expanded about 90 times. The
  `iter`/`iterq` builtins exist three times. The fork-plan dispatch is written
  four times. UI widgets spell each property five to nine times. The fuzzer has
  seven child-process runners. Two operator tables sit beside `BinOp`.
- **Invalid states.** The evaluation view is three states in two bools. A
  lowered `CallSite` keeps every field alive. `Level::GENERIC` is a sentinel.
- **Docs.** Design docs cite ~17 renamed or deleted identifiers.
  `parallel_eval.md` and `program_image.md` describe unbuilt or older machinery.
  The "ASPIRE: does not fuse yet" notes in tests are false.
