The Graphix Programming Language

sys::net - Netidx Operations

The sys::net module provides publish/subscribe and RPC operations via netidx.

sys::net::call runs calls side by side. Each fire of its arguments starts a call, named by #id (an id call_id minted) or by a fresh id, and every call answers (id, result) once: its reply, an error, or `Aborted. The answers come in the order they arrive, one a cycle, so a fast call is never held behind a slow one. A new call cancels nothing, except that a call under an id still in flight replaces that call, which answers `Aborted. One id for a search box keeps only the latest query in flight:

let query = "graphix";
let search = sys::net::call_id(null);
let (_, reply) = sys::net::call(#id: search, "/local/search", {q: query});
let hits: Array<string> = reply$;

sys::net::abort_call(id) aborts the call in flight under id from anywhere in the program: it answers `Aborted and its reply is ignored. Aborting, replacing or abandoning a call stops the wait, not the server: netidx has no cancel, so the handler still runs and its effects still happen. When the select arm holding the call sleeps, its calls in flight are abandoned and answer nothing. The last completed result survives the sleep, and waking alone sends no request. When a result must be observed, keep the call outside the sleeping arm or in a seq step that waits for it.

sys::net::callq(path, args) is the common case: no id goes in or comes out, and the answers come in the order the calls were made. Each fire of an argument still starts a call at once, so any number run side by side, but an answer that comes before an earlier call's waits for it, so a call the server never answers holds every later answer. Each call answers once, one a cycle: its reply or an error. Nothing can replace or abort a callq call, so its result has no `Aborted. When its arm sleeps, its calls in flight are abandoned and the answers waiting behind them are dropped.

let sku = "graphix-mug";
let price: f64 = sys::net::callq("/local/price", {sku})$;

callq shares nothing with other call sites, so a fan-out over it (an array::map over requests, a server's handlers) can run in parallel. call cannot: any site may name a call's id, so the calls of a fan-out over call run in program order.

type Table = { rows: Array<string>, columns: Array<string> };
type RpcArg<'a> = { default: 'a, doc: string };

/// Write the value to the specified path. Values that fire while the path
/// is bottom or invalid queue, the most recent 1024, and are written in
/// order when a valid path arrives. When its arm wakes, the write attaches
/// to the path again and writes only when the value or the path fires.
val write: fn<'a: Data>(path: string, value: 'a) -> Result<_, `WriteError(string)>;

/// subscribe to the specified path
val subscribe: fn<'a: Concrete>(path: string) -> Result<'a, [`SubscribeError(string), `InvalidCast(string)]>;

/// A call's id: equal only to itself, ordered by when it was minted, so
/// it keys a map. It is not data: no writer takes it, and it prints as
/// `abstract:`.
type RpcId;

/// A fresh id at each fire of `e`.
val call_id: fn(e: Any) -> RpcId;

/// Call the procedure at `path` with `args`, a struct or null. Each fire
/// of an argument starts a call, named `#id`, or a fresh id when `#id` is
/// null; a new call cancels nothing and waits for nothing. Each call
/// answers `(id, result)` once: its reply, an error, or `` `Aborted ``.
/// The answers come in the order they arrive, one a cycle, a fast one
/// never behind a slow one. A call under an id that is still in flight,
/// from this call site or another, replaces it: the old call answers
/// `` `Aborted ``. When the call site's arm sleeps, the calls it has in
/// flight are abandoned and answer nothing. Aborting, replacing or
/// abandoning a call stops the wait for its reply: the server is not
/// told, its handler still runs and its effects still happen. A
/// completed result survives a sleep; waking starts no call unless an
/// argument fires. When the answers are wanted in the order the calls
/// were made and no call is aborted, `callq` is simpler.
val call: fn<'a: Data, 'b: Concrete>(
    ?#id: [RpcId, null],
    path: string,
    args: 'a
) -> (RpcId, Result<'b, [`RpcError(string), `InvalidCast(string), `Aborted]>);

/// Call the procedure at `path` with `args`, a struct or null, answering
/// in call order. Each fire of an argument starts a call at once, and any
/// number may be in flight. Each call answers once, its reply or an
/// error, in the order the calls were made, one a cycle: an answer that
/// comes before an earlier call's waits for it, so a call the server never
/// answers holds every later answer. No id is taken or returned, so
/// nothing replaces or aborts a call. When the call site's arm sleeps,
/// its calls in flight are abandoned and the answers waiting behind them
/// dropped: none of them answers. The server is not told: its handler
/// still runs and its effects still happen. A completed result survives
/// a sleep; waking starts no call unless an argument fires.
val callq: fn<'a: Data, 'b: Concrete>(
    path: string,
    args: 'a
) -> Result<'b, [`RpcError(string), `InvalidCast(string)]>;

/// At each fire of `id`, abort the call in flight under it, from any call
/// site: it answers `` `Aborted ``, and its reply, when it comes, is
/// ignored. An id not in flight (answered, or never used) is left alone.
/// The server is not told: its handler still runs. A call's fresh id
/// arrives only with its answer, so a call to be aborted while it waits
/// is named with `call_id`.
val abort_call: fn(id: RpcId) -> null;

/// Publish an rpc,
/// - spec ('spec) must be a struct where every field is a RpcArg, or null (no arguments)
/// - the argument to f ('args) must be a struct with the same fields as 'spec,
///   or null if 'spec is null
/// - every field in 'args must contain the type of the corresponding default in 'spec
/// Each call runs an instance of f of its own and is answered by its first
/// value. One whose f raises is answered a generic `RpcError`, the error
/// logged here (an error's chain names the server's source): an f that
/// wants the caller to see details answers its own error value. A call runs
/// to its answer whether or not the caller is still waiting; one f never
/// answers holds the call. Past `#max_inflight` calls (1024 by default)
/// unanswered, a new call is answered an `RpcError`, as is one whose
/// arguments do not cast to f's argument type, with the cast's message.
val rpc: fn<'spec: Data, 'result: Data, 'args: Concrete + Data>(
    #path:string,
    #doc:string,
    #spec:'spec,
    ?#max_inflight:i64,
    #f:fn(args: 'args) -> 'result throws 'e
) -> Result<_, `PublishRpcError(string)> throws 'e;

/// list paths under the specified path, in order, again at each `#update`
/// (every second by default); a listing equal to the last is not answered.
val list: fn(?#update:Any, path: string) -> Result<Array<string>, `ListError(string)>;

/// list the table under the specified path, its rows and columns in order,
/// again at each `#update` as `list` does.
val list_table: fn(?#update:Any, path: string) -> Result<Table, `ListError(string)>;

/// Publish the specifed value at the specified path. A write to it is cast
/// to #on_write's argument type, and a value that does not cast answers the
/// writer with the cast's message as its error. Without a handler the
/// publication takes no writes, and while the handler is null a write
/// answers the writer with an error.
val publish: fn<'v: Data, 'a: Concrete + Data>(?#on_write:[fn(v: 'a) -> _ throws 'e, null], path: string, v: 'v) -> Result<_, `PublishError(string)> throws 'e;
