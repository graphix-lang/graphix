The Graphix Programming Language

toml

The toml module provides TOML serialization and deserialization. Like json::read, toml::read uses type-directed deserialization, and the writers write a value as its type says, as json::write_str does: a document is a struct or a map keyed by strings; an Array<(string, T)> is refused as a document. As with json, only a value whose type says nothing (Any) is written by its contents, where an array of (string, _) pairs in key order is a table.

Every union in a type toml::read reads or toml::write_str writes is one member beside null, or members each carrying a tag, as with json. An abstract value is a table of one entry its type's name keys ({ Port = 80 }), the data inside in the form its reader reads (abstract values bare, untagged, in the data a from_value reads), and Transparent<T> writes it bare.

TOML has no null. A struct field that is null is left out, and a key the document leaves out reads as null where the field's type admits it, so an optional field reads back. A null anywhere else, an array's element, a map's value or what an abstract type writes, is refused when written. TOML cannot write a duration or a decimal either, and has a datetime of its own.

A map is a table when its key type is string and an array of [key, value] pairs under any other, which must be inside a document field because TOML requires a table at the root: toml::write_str of a Map<i64, string> is refused by its type, and of such a map under Any when written. toml::read reads such a map from a document's entries. Bytes write as an array of byte integers.

/// Parse TOML from a string or bytes.
///
/// To parse a stream, read it first — `toml::read(Read::read_all(f)?)`.
/// The target reads back what `write_str` writes of it (`TomlData`), as
/// `json::read`'s does: every union in it tells its members apart by a
/// tag, or is one member and null.
val read: fn<'b: Concrete + TomlData>(input: [string, bytes]) -> Result<'b, [`TomlErr(string), `InvalidCast(string)]>;

/// Serialize a value to a TOML string, as `json::write_str` does: a map
/// is a table when its key type is `string` and an array of `[key,
/// value]` pairs, which needs a table around it, under any other, so such
/// a map is refused as the document itself (by its type, or by the value
/// where its type is `Any`); an
/// abstract value is a table of one entry its type's name keys (`{ Port
/// = 80 }`), or under `Transparent` its data alone, the data inside as
/// `json::write_str` writes it. TOML has no null: a
/// struct field that is null is left out, and reads back as null; a null
/// anywhere else is refused when written. The value's type must be one
/// `read` reads back (`TomlData`).
val write_str: fn<'a: Data + TomlData>(?#pretty: bool, value: 'a) -> Result<string, `TomlErr(string)>;

/// Serialize a value to TOML bytes, as `write_str` does.
///
/// To write to a stream, write the bytes — `Write::write_exact(f, toml::write_bytes(v)?)`.
val write_bytes: fn<'a: Data + TomlData>(?#pretty: bool, value: 'a) -> Result<bytes, `TomlErr(string)>;

Example


type Config = {
    host: string,
    port: i64,
    debug: bool
};

let cfg: Config = toml::read(sys::fs::read_all("config.toml")?)?;
let out = toml::write_str(#pretty: true, cfg)?;

A writer refuses a map whose distinct keys serialize as the same data, including when the map uses the pairs representation.
